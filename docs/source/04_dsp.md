# 4. Аудио-конвейер и определение высоты тона

## 4.1. Почему это не «просто FFT»

Колебание гитарной струны — почти периодический сигнал с богатым набором обертонов:
у 6-й струны (E2, 82,4 Гц) в спектре 20+ значимых гармоник, причём вторая и третья часто
громче основного тона. Классический «максимум спектра» поэтому ошибается в разы:
на E2 при частоте дискретизации 48 кГц и окне 4096 отсчётов бин БПФ равен 11,7 Гц — это
**250 центов**, то есть полтора тона. Никакой интерполяцией пика это не лечится на низких струнах.

Дополнительные сложности реального сигнала:

| Явление | Что происходит | Следствие для алгоритма |
| --- | --- | --- |
| Атака щипка | 20–60 мс широкополосного шума и резкого роста амплитуды | первые кадры отбрасываются или помечаются низкой достоверностью |
| Затухание | уровень падает на 20–40 дБ за 2–3 с | нужен порог тишины с гистерезисом |
| Биения и расстроенность | две струны или обертоны дают амплитудную модуляцию | сглаживание по времени, а не по частоте |
| Перегруз электрогитары | клиппинг, интермодуляция, «октавный» призвук | проверка октавных кандидатов (4.3.4) |
| Речь и шум | непериодический сигнал с формантами | порог `clarity` и RMS-гейт |
| Флажолет | почти чистая синусоида выше по частоте | корректно обрабатывается как обычная нота |

Поэтому используется **автокорреляционный метод с нормализацией** — NSDF/McLeod Pitch Method (MPM):
он ищет период напрямую во временной области, устойчив к тембру и не требует, чтобы основной тон
был самым громким в спектре.

## 4.2. Параметры анализа

### 4.2.1. Базовые значения

| Параметр | Значение | Обоснование |
| --- | --- | --- |
| Частота дискретизации `fs` | 48 000 Гц (приоритет), 44 100 Гц (fallback) | нативный режим микрофона; 22,05 кГц не хватит для точности на высоких ладах |
| Окно анализа `N` | 4096 отсчётов (85,3 мс при 48 кГц) | ≥ 5 периодов для E2 (82 Гц); компромисс «точность/задержка» |
| Шаг `hop` | 1024 отсчёта (21,3 мс) | перекрытие 75 %, ~47 обновлений/с |
| Диапазон поиска периода `τ` | `τ_min = fs / 1400 ≈ 34`, `τ_max = fs / 30 = 1600` | покрывает 30–1400 Гц; `τ_max` уточняется по строю |
| Порог тишины (вход) | RMS < −50 dBFS | ниже — состояние «Слушаю…» |
| Порог тишины (выход) | RMS > −45 dBFS | гистерезис 5 дБ против мигания |
| Минимальная достоверность `clarity` | 0,60 | ниже — оценка не показывается |
| Сглаживание | медиана 5 кадров + EMA α = 0,30 по `log2(f)` | подавление выбросов и дрожания |
| Допуск «в строе» | ±3 цента, удержание 250 мс | соответствует ФТ-07 |

### 4.2.2. Почему окно адаптивное

При 2048 отсчётах (42,7 мс) на E2 укладывается 3,5 периода, и параболическая интерполяция
даёт разброс ±3…5 центов даже на чистой синтетике. Окно 4096 снижает разброс до ±0,5 цента
и остаётся базовым для всех строёв с нижней нотой ≥ 82 Гц.

Для низких строёв (виолончель C2, контрабас E1, бас B0) 4096 даёт всего 2–3 периода на самой
низкой струне — растут октавные ошибки. Поэтому окно выбирается по нижней ноте строя (4.2.3),
а не глобально.

### 4.2.3. Пониженные строи и бас

Для строёв с нижней нотой ниже E2 окно увеличивается (виолончель C2, контрабас E1, бас B0):

| Нижняя нота строя | `N` | `τ_max` | Задержка | Голоса | Точность |
| --- | --- | --- | --- | --- | --- |
| ≥ E2 (82,4 Гц) | 4096 | 686 | 85 мс | гитара, скрипка, альт, укулеле, мандолина, домра, банджо | ±1 цент |
| C2–D#2 (65–78 Гц) | 8192 | ≈ 780 | 171 мс | виолончель, drop C, 7-струнная гитара | ±2 цента |
| B0–B1 (30–62 Гц) | 16384 | до 1600 | 341 мс | бас-5, контрабас, бас-4 | ±3 цента |

Правило: `N` выбирается по **активному строю**, а не глобально. Для хроматического режима
действует 4096, пока пользователь не включит «Низкий диапазон» в настройках — тогда 16384.
НФТ-02 становится трёхуровневой: 120 / 200 / 400 мс. Это осознанное исключение, зафиксированное
в разделе 10 (D-3).

### 4.3.1. Подготовка кадра

1. **Приведение к float.** Оба бэкенда (cpal и oboe) отдают `f32` в диапазоне −1…1, конвертация не нужна. WAV-фикстуры 16 бит приводятся в тесте: `x[i] = s[i] as f32 / 32768.0`.
2. **Удаление постоянной составляющей.** Вычитается среднее по окну. Обязательно: смещение нуля
   даёт ложный пик NSDF на больших `τ`.
3. **Фильтр верхних частот** (one-pole, `fc = max(40 Гц, 0,6 · f_нижн_строя)`): убирает гул,
   вибрацию корпуса и шум-handling. Формула: `y[i] = a · (y[i-1] + x[i] − x[i-1])`,
   `a = 1 / (1 + 2π · fc / fs)`.
4. **Оценка уровня:** `rms = sqrt(mean(x²))`, `dBFS = 20 · log10(rms + 1e-9)` — для гейта и
   мини-индикатора уровня (ФТ-14).

### 4.3.2. NSDF (нормированная автокорреляционная функция)

Для `τ` в диапазоне `[τ_min, τ_max]`:

$$
n(\tau) = \frac{2 \sum_{j=0}^{N-1-\tau} x_j \, x_{j+\tau}}
{\sum_{j=0}^{N-1-\tau} \left(x_j^2 + x_{j+\tau}^2\right)}
$$

Свойства, которые важны для реализации:

- `n(0) = 1`, значения ограничены `[−1, 1]`, поэтому **clarity сравнима между кадрами и громкостями**;
- на истинном периоде `n(τ)` имеет локальный максимум, близкий к 1;
- нормировка на энергию компенсирует затухание внутри окна.

### 4.3.3. Выбор пика (правило McLeod)

Простой «глобальный максимум» даёт октавные ошибки: у сигнала с сильной второй гармоникой
максимум NSDF может оказаться на `2τ`. Поэтому:

1. Найти все локальные максимумы `n(τ)` при `τ ≥ τ_min`.
2. Вычислить `n_max` — глобальный максимум.
3. Выбрать **наименьший** `τ_k`, для которого `n(τ_k) ≥ κ · n_max`, где `κ = 0,90`.
4. Отбросить пики, у которых `τ` меньше `0,7 · τ_k` (защита от кратных пиков).

Параметр `κ` — единственная «ручка» алгоритма: меньше `κ` — устойчивее к пропаданию основного тона,
но выше риск выбрать субгармонику. Значение 0,90 проверяется на тестовом наборе 4.6.

### 4.3.4. Уточнение периода и проверка октав

Параболическая интерполяция по трём точкам вокруг выбранного максимума:

$$
\tau^{*} = \tau_k + \frac{n_{k-1} - n_{k+1}}
{2\left(n_{k-1} - 2n_k + n_{k+1}\right)}
$$

Частота: `f = fs / τ*`. Достоверность: `clarity = n(τ_k)`, ограниченная сверху 1.

Проверка октав (важна для перегруженной электрогитары и низких струн):

```text
если clarity(f) < 0.75 и существует кандидат f/2 с clarity(f/2) ≥ 0.85:
    принять f/2
если clarity(f) < 0.75 и существует кандидат 2f с clarity(2f) ≥ 0.90:
    принять 2f
```

В режиме «По струнам» дополнительно проверяется согласованность с целевыми частотами:
кандидат, попадающий в ±50 центов от целевой струны, предпочтительнее кандидата, отличающегося
на 12 полутонов (см. 4.4).

### 4.3.5. Сглаживание

Сглаживание выполняется **в логарифмической шкале и без привязки к опорной частоте**:

1. `y_i = 1200 · log2(f_i / 440)` — абсолютная высота в центах относительно A4 = 440 Гц.
2. Медиана по последним 5 значениям `y` — убирает одиночные выбросы (щелчки, скрип).
3. EMA: `s_i = α · y_med + (1 − α) · s_{i-1}`, `α = 0,30`; при первом кадре `s_i = y_med`.
4. При разрыве сигнала (переход в «Слушаю…» дольше 400 мс) фильтр сбрасывается, чтобы
   индикатор не «приползал» из старого значения.

Так как сглаживаются центы, а не частоты, смена опорной частоты A4 не вызывает скачка
и не требует пересчёта истории: меняется только целевая частота.

### 4.3.6. Маппинг в ноту и центы

Целевая частота ноты `m` (MIDI, где A4 = 69) при опорной `f_A4`:

$$
f_t(m) = f_{A4} \cdot 2^{(m - 69)/12}
$$

Отклонение в центах:

$$
c = 1200 \cdot \log_2 \frac{f}{f_t}
$$

Ближайшая нота в хроматическом режиме: `m = round(69 + 12 · log2(f / f_A4))`.

Режим «По струнам»: для каждой струны строя считается `c_k`, выбирается минимум `|c_k|`.
Гистерезис: если текущая струна `s` и новая `s'` отличаются меньше чем на 2 цента по `|c|`,
остаётся `s`; переключение происходит только при выигрыше новой струны ≥ 10 центов или при
выходе текущей за пределы ±60 центов. Это устраняет дребезг на границе E2/E3 при октавной ошибке.

### 4.3.7. Псевдокод кадра

```rust
impl PitchDetector {
    /// Обрабатывает кадр in-place: без аллокаций и без изменения длины.
    pub fn process_frame(&mut self, raw: &mut [f32], fs: u32) -> Option<Estimate> {
        // 1. подготовка
        dc_remove(raw);
        self.high_pass(raw, fs);
        let db = level_db(raw);

        // 2. гейт с гистерезисом
        if db < self.gate_db - 5.0 {
            return None; // тишина
        }
        if db < self.gate_db {
            return Some(Estimate::Silent);
        }

        // 3. NSDF
        let tau_min = (fs / 1400).max(2) as usize;
        let tau_max = (fs as f32 / self.f_min_hz) as usize;
        self.nsdf(raw, tau_min, tau_max);

        // 4. пик по правилу McLeod + интерполяция
        let peak = self.first_peak_above(0.90)?;
        let tau = self.parabolic_refine(peak);
        let f0 = fs as f32 / tau;
        let clarity = self.nsdf[peak];

        if clarity < self.clarity_min {
            return Some(Estimate::Uncertain { clarity });
        }
        Some(Estimate::Pitch { f0, clarity, db })
    }
}
```

Все рабочие буферы (`nsdf`, окно, фильтр) — поля структуры, созданные один раз:
`process_frame` не выделяет память, поэтому может вызываться из аудио-потока без риска
для real-time бюджета.

## 4.5. Производительность и альтернативы

**Стоимость NSDF «в лоб»:** для каждого `τ` выполняется `N − τ` умножений, суммарно
`Σ(N − τ) ≈ N · τ_max − τ_max²/2 ≈ 2,4 млн` умножений-сложений на кадр при `N = 4096`,
`τ_max = 686`. При 47 кадрах/с это ~113 млн операций/с. На Rust это укладывается
в 1,5–3 мс на Cortex-A78 даже без ручного SIMD (LLVM векторизует внутренний цикл),
но требует аккуратной реализации:

- один проход по `τ` с накоплением числителя и знаменателя, без промежуточных `Vec`;
- `f32` в горячем цикле, `f64` только для `log2` и интерполяции;
- `std::hint::black_box` в бенчмарках, чтобы LLVM не выбросил расчёт;
- `codegen-units = 1`, `lto = true` в release-профиле — иначе автовекторизация страдает.

**Если бюджета не хватает:** автокорреляция через FFT на crate `realfft`. Паддится до 16384, `|FFT|²`, обратное
преобразование; сложность `O(N log N) ≈ 230 тыс.` операций вместо 2,4 млн. Цена — зависимость
от библиотеки FFT (или своя реализация radix-2, ~150 строк) и чуть большая погрешность
на краях окна (лечится тем же окном Ханна и нормировкой). Решение принимается по замеру,
а не заранее.

**Сравнение алгоритмов:**

| Метод | Точность на E2 | Устойчивость к тембру | Стоимость | Вердикт |
| --- | --- | --- | --- | --- |
| Zero-crossing | плохая (обертоны дают лишние переходы) | низкая | очень низкая | не подходит |
| Пик БПФ | ±250 центов при N=4096 | низкая | низкая | не подходит |
| HPS (harmonic product spectrum) | ±10–20 центов | средняя | средняя | резерв |
| YIN (CMNDF) | ±1–2 цента | высокая | средняя | эквивалент MPM |
| **MPM / NSDF** | **±0,5–1 цент** | **высокая** | **средняя** | **выбран** |
| CQT | высокая | высокая | высокая | избыточно для 6 струн |

## 4.6. Точность, тестовые сигналы и допуски

Тестирование DSP не может зависеть от живой гитары, поэтому эталоны генерируются скриптом
`tools/gen_fixtures.py` и коммитятся в репозиторий вместе с манифестом истинных частот.

| Тип сигнала | Параметры генерации | Допуск |
| --- | --- | --- |
| Чистая синусоида | 30–1400 Гц, шаг 1 %, уровень −20 dBFS | ≤ 0,5 цента |
| Низкие ноты (B0–C2) | 30–65 Гц, окно 16384 | ≤ 3 цента, 0 октав |
| Унисонные струны | E4+E4, A4, окно 4096 | ≤ 1 цент, правильная пара |
| Гармонический ряд | 6 гармоник, спадание 1/n…1/n², случайные фазы | ≤ 1 цент |
| Karplus–Strong (щипок) | 20 нот от E2 до E4, 3 реализации на ноту | ≤ 1 цент, 0 октавных ошибок |
| Модель перегруза | `tanh(3x)` после гармонического ряда | ≤ 2 цента, 0 октавных ошибок |
| Сигнал с шумом | SNR 20, 10, 6 дБ | ≤ 1 / 2 / 4 цента соответственно |
| Речь (негативный тест) | 10-секундные фрагменты, 2 диктора | 0 ложных «нот» при `clarity ≥ 0,60` |
| Тишина / шум комнаты | −60 dBFS белый шум | состояние `Silent`, без цифр |

Набор хранится как WAV 48 кГц/16 бит моно; для 44,1 кГц те же сигналы пересчитываются
ресемплингом в тесте (проверка, что `fs` берётся из фактического потока, а не из константы).

Метрики, которые считает тест:

- `maxAbsCents` — максимум модуля ошибки по всем кадрам устойчивой части (после 100 мс от начала);
- `octaveErrorRate` — доля кадров, где ошибка кратна 1200 центам;
- `detectionRate` — доля кадров с `clarity ≥ 0,60` на участке, где сигнал есть;
- `latencyFrames` — сколько кадров от начала звука до первого верного результата (норма ≤ 3).

## 4.7. Краевые случаи

| Случай | Поведение |
| --- | --- |
| Струна сильно расстроена (> 100 центов) | показывается ближайшая хроматическая нота и направление; автоопределение струны не переключается, пока отклонение не станет < 100 центов |
| Две струны звучат одновременно | `clarity` падает, состояние `Uncertain`, подсказка «глушите лишние струны» |
