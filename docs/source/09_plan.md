# 9. План работ

## 9.1. Объём MVP

**Входит:** ФТ-01…ФТ-17, НФТ-01…НФТ-14, Android + macOS, ru/en, 11 инструментов + хроматический,
встроенные и пользовательские строи, опорная частота с вводом, айдентика и иконки,
Rust-ядро, Tauri-оболочка, Kotlin-шим разрешений и вибрации, раздача через GitHub Releases.

**Не входит:** iOS, Mac App Store, аккаунты, облако, экспорт строёв, стробоскоп, метроном,
определение аккордов, генератор тона, аналитика.

## 9.2. Оценка

- **Опытный Rust-разработчик** — 32–38 рабочих дней (35 с буфером). Рост относительно гитарной
  версии: +2 дня UI, +2 дня данные инструментов, +2 дня айдентика/иконки, +1 день DSP на низкий
  диапазон; −1 день на notarization и стор, которых нет; +5–7 дней на Windows и Linux.
- **Разработчик, новый для Rust** — 40–48 дней.
- **Два разработчика** — 18–22 дня: ядро/DSP и UI разводятся, платформы параллелятся.

Оценка не включает Apple Developer Program, ревью Google Play и юридическую проверку имени.

## 9.3. Этапы и критерии готовности

| Этап | Дни | Работы | Готово, когда |
| --- | --- | --- | --- |
| 0. Каркас | 3 | workspace, `tauri init` (desktop + Android), Vite/Svelte, CI, сертификат Apple | `cargo test` и `npm run tauri build` зелёные, пустое окно на macOS и Android, CI проходит |
| 1. Ядро музыки | 2 | `NoteMath`, инструменты, строи, `InstrumentRegistry`, выбор окна | unit-тесты на все строи 5.5, A2 при 442 = 110,50 Гц, скрипка/виолончель/бас дают верные целевые частоты |
| 2. DSP | 5 | NSDF, пик, интерполяция, гейт, сглаживание, октавы, адаптивное окно 4096/8192/16384 | фикстуры 8.3 проходят для всех групп, `criterion` в бюджете, 0 октавных ошибок на Karplus–Strong и низких нотах |
| 3. UI | 7 | экран тюнера, нониус, лист «Инструмент · Строй», хроматика, лист A4 с вводом, настройки, редактор, язык | все переходы работают на моковых данных, `vitest` на сторах, 16/24/32 px проверены |
| 4. macOS | 4 | `cpal`, trait `AudioSource`, окно и меню Tauri, `tuner-storage`, DMG | настройка гитары и скрипки на Mac, DMG запускается, чек-лист п. 10–12, 14 |
| 5. Android | 5 | NDK, `oboe`, Kotlin-шим (разрешение, вибрация, keep screen on), жизненный цикл | настройка на 2 устройствах, чек-лист п. 1–3c, 8, 9, 15 |
| 6. Полировка | 2 | доступность, темы, крупный шрифт, микрокопия, ошибки, reduced-motion | чек-лист 8.4 полностью |
| 7. Выпуск | 2 | per-arch DMG (aarch64, x86_64), ad-hoc подпись, APK с собственным ключом, GitHub Releases, README «Первый запуск» | критерии 2.6: DMG запускается после «Всё равно открыть», APK ставится sideload |
| 8. Айдентика | 1–2 | мастер-иконка, `.icns`, `.ico`, adaptive, шапка README | иконка в Dock, на домашнем экране и в Explorer, 16 px читается |
| 9. Windows | 2 | WASAPI через `cpal`, WebView2, NSIS, иконка `.ico` | установка на Windows 10/11, микрофон и меню работают |
| 10. Linux | 3 | ALSA/PipeWire, WebKitGTK, AppImage и `.deb` | запуск на Ubuntu 24.04 и Fedora 40, звук работает |

Айдентика (этап 8) может идти параллельно с этапами 2–5: знак уже выбран, нужны только
финальные файлы. Итог: **32–38 дней**, буфер 2 дня внутри этапа 7.

## 9.4. Порядок, который нельзя менять

1. **Сначала данные инструментов и DSP, потом микрофон.** Строи и целевые частоты проверяются
   юнит-тестами до подключения аудио.
2. **Сначала macOS, потом Android.** Цикл правки на macOS — секунды, на Android — минуты плюс NDK.
3. **Сначала один экран, потом настройки.** Настройки без работающего тюнера — макет.
4. **Сертификат Apple и профиль notarytool — на этапе 0.**
5. **`unsafe` только в `tuner-audio`.** Любой `unsafe` в `tuner-core` — повод для ревью.
6. **Айдентику не перерисовывать вручную.** Все размеры — из `brand/src/unisono-mark.svg`.
