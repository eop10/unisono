(adr-001)=

## ADR-001. Rust-ядро и Tauri 2 как оболочка для Android и macOS

**Контекст.** Нужны две платформы, точный DSP и низкоуровневый доступ к микрофону; продукт
мультиинструментальный (струнные + хроматика), маленький и полностью офлайновый.

**Решение.** Workspace на Rust: `tuner-core` (DSP, инструменты, строи, без I/O),
`tuner-audio` (cpal/oboe), `tuner-storage` (JSON), `src-tauri` (Tauri 2, команды и канал состояний).
UI — один на обе платформы на Svelte + TypeScript в системном WebView.

**Следствия.**

- (+) Нет JVM и GC: DMG ~10–20 МБ, APK ~8–12 МБ, предсказуемые задержки.
- (+) Один UI; нативное окно и меню macOS через API Tauri.
- (+) `tuner-core` тестируется на любой ОС, включая CI без Android SDK; данные инструментов
  и строёв не зависят от UI.
- (−) WebView: вид не нативный; разрешения, вибрация и keep-screen-on требуют Kotlin-шима.
- (−) Мобильный тулинг Tauri моложе Compose/Flutter; обновления проверяются вручную.

**Альтернативы.** Rust-ядро + SwiftUI/Compose (+2–3 недели, два UI); Slint; Kotlin Multiplatform
(JVM, GC, 60–80 МБ). Переход на нативные оболочки не затрагивает `tuner-core` и `tuner-audio`.

## ADR-002. Определение высоты тона методом NSDF/MPM

**Контекст.** Нужна точность ±1 цент в 80–700 Гц, устойчивость к тембру и перегрузу, работа
на телефоне без сторонних DSP-библиотек, диапазон до 30 Гц для баса и контрабаса.

**Решение.** McLeod Pitch Method: NSDF, выбор первого пика выше `0,90 · max`, параболическая
интерполяция, `clarity`, октавная коррекция, сглаживание в логарифмической шкале. Буферы — поля
структуры, ноль аллокаций в `process_frame`.

**Следствия.**

- (+) Точность ±0,5–1 цент на реальных тембрах, устойчивость к отсутствию основного тона.
- (+) `clarity` — естественный порог для «нет сигнала».
- (+) ~300 строк безопасного Rust; LLVM векторизует цикл.
- (−) Стоимость `O(N · τ_max)`; на 16384 отсчётах нужен FFT-резерв (`realfft`).
- (−) Требует калибровки `κ` и порогов на фикстурах.

**Альтернативы.** YIN, HPS (±10–20 центов — мало), пик БПФ (не годится для низких струн), CQT.

(adr-003)=

## ADR-003. Без базы данных: `serde_json` и два файла

**Контекст.** Хранятся единицы настроек и до 20 строёв на инструмент. Нужны миграции и переносимость.

**Решение.** `tuner-storage`: `settings.json` и `presets.json`, `serde` + `serde_json`,
`schema_version`, атомарная запись (tmp + `sync_all` + `rename`).

**Следствия.**

- (+) Нет SQLite/`rusqlite`: меньше размер, нет схемы БД.
- (+) Файл строёв можно открыть и прислать в поддержку.
- (−) Валидация и версионирование — на нас (5.7–5.8).
- (−) Один процесс — конкурентная запись не поддерживается.

**Альтернативы.** `rusqlite` (избыточно), `toml`/`ron`, хранение строёв только в коде.

(adr-004)=

## ADR-004. Захват звука: `cpal` на macOS, `oboe` на Android, `rtrb` между ними

**Контекст.** Нужен сырой PCM без обработки, минимальная задержка, отсутствие аллокаций
в real-time потоке и диапазон до 30 Гц.

**Решение.** trait `AudioSource`; macOS — `cpal` (CoreAudio, `f32`, буфер 512 кадров);
Android — `oboe` (`AudioFormat::Float`, `InputPreset::VoiceRecognition`, 48 кГц);
передача кадров — lock-free SPSC `rtrb`; анализатор — отдельный `std::thread`.

**Следствия.**

- (+) Полный контроль над форматом и отключением AGC/NS на обеих платформах.
- (+) Нет аллокаций и блокировок в колбэке — нет щелчков.
- (+) Один trait, две реализации; DSP не знает, откуда кадры.
- (−) `oboe` требует NDK и аккуратной обработки ошибок открытия.
- (−) `cpal` чувствителен к смене устройства — нужен перезапуск потока.
- (−) Переполнение `rtrb` при отставании анализатора считается, а не роняет поток.

**Альтернативы.** `cpal` на Android (менее предсказуем); `AVAudioEngine` через `objc2`;
Web Audio в WebView (не подходит).

## ADR-005. Распространение через GitHub Releases без магазинов

**Контекст.** У разработчика нет Apple Developer Program и аккаунта Google Play; приложение
бесплатное и офлайновое, исходники открыты. Нужен работающий канал установки без затрат.

**Решение.** Публичный репозиторий на GitHub, релизы через **GitHub Releases**:

- macOS — **Universal DMG** (arm64 + x86_64), `.app` подписан **ad-hoc** (`codesign -s -`),
  без notarization;
- Android — **APK, подписанный собственным keystore** (self-signed), без Google Play;
- рядом с файлами — SHA-256; в README — блок «Первый запуск» для macOS 14 и 15+
  и инструкция sideload для Android.

**Следствия.**

- (+) Ноль затрат, полный контроль, мгновенные релизы, исходники рядом.
- (+) Один DMG на все Mac; нет выбора архитектуры.
- (+) Подпись Android своим ключом — штатная практика для F-Droid и GitHub-раздачи.
- (−) Gatekeeper предупреждает при первом запуске; часть пользователей не установит.
- (−) Play Protect может предупредить о sideload; корпоративные Mac с MDM могут блокировать.
- (−) Нет автообновлений из стора; обновление — вручную или через Tauri updater (свои ключи).
- (−) Потеря Android-keystore означает невозможность обновить приложение поверх.
- (−) Имя `app.unisono.tuner` не защищено стором; при появлении аккаунтов его нужно проверить.

**Альтернативы.** Apple Developer Program (99 $/год) + notarization — убирает предупреждение,
добавляет 1–3 дня на оформление; Google Play (25 $) — витрина и обновления, но требует аккаунт,
политику и ревью. Оба варианта можно добавить позже без изменения кода и bundle id.

## ADR-006. Мультиинструментальность и адаптивное окно анализа

**Контекст.** Тюнер должен работать не только с гитарой: скрипка E5 (659 Гц), виолончель C2
(65 Гц), контрабас и 5-струнный бас B0 (30,9 Гц). Фиксированное окно 4096 не даёт точности
на низких нотах, а фиксированное 16384 убивает отзывчивость на высоких.

**Решение.**

1. Модель **инструмент → строй → струны**; встроенные данные в `music/instruments.rs`
   и `music/tunings.rs`; пользовательские строи привязаны к инструменту.
2. Хроматический режим — инструмент `chromatic` без струн (ФТ-06).
3. Окно анализа выбирается по нижней целевой ноте строя:

| Нижняя нота | `N` | `τ_max` | Задержка | Точность |
| --- | --- | --- | --- | --- |
| ≥ E2 (82 Гц) | 4096 | 686 | 85 мс | ±1 цент |
| C2–D#2 (65–78 Гц) | 8192 | ~780 | 171 мс | ±2 цента |
| B0–B1 (30–62 Гц) | 16384 | до 1600 | 341 мс | ±3 цента |

4. Дубли нот в строе разрешены (балалайка E4+E4, мандолина): автоопределение подсвечивает пару.

**Следствия.**

- (+) Один код обслуживает 11 инструментов + хроматику; добавление инструмента — данные, не UI.
- (+) Точность и задержка сбалансированы по диапазону.
- (−) НФТ-02 становится трёхуровневой (120/200/400 мс).
- (−) Низкие струны требуют более длинного устойчивого звука; нужна подсказка.
- (−) Появляется правило унисонов, которого не было в гитарной версии.

**Альтернативы.** Фиксированное 8192 (медленно для скрипки, неточно для баса); отдельные
приложения по инструментам (дублирование); ресемплинг вниз (лишняя сложность).

## ADR-007. Айдентика: Unisono и знак «U + точка»

**Контекст.** Продукт перестал быть «гитарным тюнером». Нужно имя, знак и иконка, которые
работают для всех инструментов и сочетаются с приборным интерфейсом.

**Решение.** Бренд **Unisono** (итал. «унисон»); в сторах — «Unisono: Instrument Tuner».
Знак — монограмма `U` (две струны) с латунной точкой в центре (унисон/«в строе»).
Палитра и типографика — из интерфейса: `#0E0F10`, `#E8E6E1`, латунь `#C8A15A`,
Roboto Flex + JetBrains Mono.

**Следствия.**

- (+) Знак не привязан к гитаре, читается в 16 px, легко рисуется в монохроме.
- (+) Совпадает с языком UI: точка — тот же «ноль» на нониусе.
- (+) Один мастер-SVG даёт `.icns`, adaptive icon и шапку GitHub.
- (−) `Unisono` уже используется: TUNIC Unisono, unisono social, `be.unisono.app`;
  в категории тюнеров есть **Unison: Piano Tuner**.
- (−) Марки не проверены (Q13); до релиза нужна юридическая проверка классов 9/15/41.
- (−) Точка на 16 px на грани различимости — допускается +10 % размера.

**Альтернативы.** `Unison` (сильнее конфликт с Piano Tuner); `Cents`, `Nonius`, `Kammerton`,
`Строй`, `Лад` (см. историю обсуждения). Знак-кольцо, знак-игла, камертон — отклонены
как менее связанные с интерфейсом.

## ADR-008. Windows и Linux как целевые платформы

**Контекст.** UI и ядро уже кроссплатформенные: Tauri 2 собирается под Windows и Linux,
`cpal` умеет WASAPI и ALSA. Пользователи просят настольные версии помимо macOS.

**Решение.** Добавить Windows 10/11 x64 и Linux x86_64 в MVP:

- тот же `tuner-core`, тот же Svelte-бандл, тот же `AudioSource`;
- Windows — `cpal`/WASAPI (shared), WebView2, NSIS-установщик, иконка `.ico`;
- Linux — `cpal`/ALSA (PipeWire через плагин), WebKitGTK 4.1, AppImage и `.deb`;
- подписи нет: SmartScreen на Windows, обычный запуск AppImage на Linux.

**Следствия.**

- (+) Один UI и одно ядро на пять платформ; новых UI-экранов нет.
- (+) Дистрибуция без магазинов и аккаунтов: GitHub Releases.
- (−) +5–7 дней: установщики, зависимости, QA.
- (−) Linux — самый рискованный: дистрибутивы, WebKitGTK, NVIDIA, ALSA/PipeWire.
- (−) Windows SmartScreen предупреждает; Authenticode-сертификат отложен.

**Альтернативы.** Только macOS/Android (уже сделано); Electron (тяжелее, не нужен);
нативные UI (дублирование). Windows/Linux можно отложить, но код и данные к ним уже готовы.

## ADR-009. Границы окон 8192/16384: B1 включительно в 8192

**Контекст.** Таблица 4.2.3 неоднозначна: 7-струнная гитара (нижняя нота B1, 61,7 Гц)
перечислена в строке окна 8192, но диапазон строки 16384 подписан «B0–B1» и тоже
включает B1. Нужно однозначное правило для `InstrumentRegistry::window_size`,
работающее и для пользовательских строёв (MIDI 21–96).

**Решение.** Границы по MIDI нижней ноты строя: `≥ 40` (E2) → 4096; `≥ 35` (B1) → 8192;
`< 35` → 16384. Обоснование физическое: `τ_max ≈ 780` окна 8192 при 48 кГц покрывает
частоты до `48000 / 780 ≈ 61,5` Гц, то есть B1 (61,7 Гц) включительно; A#1 (58,3 Гц)
требует `τ ≈ 824 > 780` и уходит в 16384. Правило совпадает со всей колонкой «Голоса»
таблицы 4.2.3: 7-струнная гитара → 8192, бас-4 (E1) и контрабас → 16384.

**Следствия.**

- (+) Однозначное правило для любого строя, включая пользовательские ниже B0.
- (+) 7-струнная гитара получает 8192 (задержка 171 мс), а не 16384 (341 мс).
- (−) Подписи диапазонов в таблице 4.2.3 пришлось уточнить: «B1–D#2» и «B0–A#1»;
  таблица дополнена ссылкой на это решение.

**Альтернативы.** Граница по частоте 65 Гц (B1 → 16384) — противоречит колонке «Голоса»
и удваивает задержку 7-струнной гитары без выигрыша в точности: при 8192 в окне
укладывается ≈ 7,5 периодов B1.
